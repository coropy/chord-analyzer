# Chord Analyzer — 操作マニュアル

MIDI/WAV を再生しながら、コードが鳴り始めた瞬間を **Enter** で手動記録し、隣接する記録点（Marker）の間から **Chord Region** を定義します。将来の Chord Analyzer に渡す、コード境界のデータを正確に素早く記録することを優先した Web アプリです。

---

## 1. 起動方法

Node.js と npm が必要です。

```bash
cd "C:\Users\alpha\OneDrive\デスクトップ\mt3\chord-analyzer"
npm install        # 初回のみ（依存パッケージを導入）
npm run dev        # 開発サーバー起動
```

Web ブラウザで **http://localhost:5173/** を開きます。

停止するときは **Ctrl+C** です。

### データファイルの読み込み

**起動直後から、内蔵のデフォルト MIDI（`./data/nakanori_mt3.mid`、1909ノート）が自動で読み込まれ、ノートが表示されます**（音声をまだ選んでいなければステータスに「音声未選択」）。

自分の曲に置き換える場合：

1. トップバーの **♪ MIDI** を押し、別の `.mid` / `.midi` ファイルを選ぶ（選ぶと即座にノート表示が置き換わる）。
2. トップバーの **♫ 音声 (WAV/MP3)** を押し、音源ファイル（WAV / MP3 / OGG / FLAC / M4A）を選ぶ。

- MIDI と音声は**独立**に読み込まれます。MIDI を選んだら即座にノート表示が更新されます。
- 音声を選ぶと **▶ Play** ボタンが有効になります。
- エラー時は「MIDIエラー: …」/「音声エラー: …」と表示されます。

**表示範囲**: ノート表示の縦方向は**そのMIDIの最高音〜最低音**に固定され、縦スクロールでこの範囲外へは移動できません。

## 2. 画面の構成

| 領域 | 内容 |
|---|---|
| **トップバー** | 再生ボタン / 位置表示 / Grid / Quantize / Undo・Redo / パフォーマンス表示 |
| **デバッグバー** | 現在位置の raw tick / quantized tick / audio 秒 / bar・beat |
| **ステージ** | 左 = ピアノ鍵盤、中央 = ピアノロール（ノート表示） |
| **トラックバー** | トラックごとの表示・非表示チェックボックス |

ピアノロールでは縦軸が MIDI の高さ（pitch）、横軸が時間（tick）です。青い縦線が **playhead（再生位置）** です。黄色い縦線が **Marker**、緑の半透明帯が **Chord Region** です。

---

## 3. 基本操作 — 再生・移動・表示

### 再生 / 停止
| 操作 | 内容 |
|---|---|
| **▶ Play / Ⅱ Pause** ボタン | 再生 / 一時停止 |
| **■ Stop** ボタン | 停止して先頭（tick 0）へ戻る |
| **Space** キー | Play / Pause の切り替え |

### シーク（場所の移動）
中央のピアノロールの空いている部分を**クリック**すると、その時間位置へ移動します。クリックはシーク専用で、**Marker は追加されません**（追加は Enter のみなので衝突しません）。

### 拡大・スクロール
| 操作 | 内容 |
|---|---|
| マウスホイール（縦回し） | 横方向（時間）の拡大 / 縮小 |
| Shift + マウスホイール | 縦方向（pitch）の拡大 / 縮小 |
| ドラッグ（左ボタン押しっぱなし） | 画面のスクロール（パン） |

拡大はマウス位置を中心に行われるため、見たい場所にマウスを合わせてから拡大すると操作しやすいです。

### トラックの表示 / 非表示
トラックバーのチェックボックスを外すと、そのトラックのノートを非表示にできます。解析対象のトラックだけに絞るのに便利です。

## 4. Marker（コード開始位置）の記録

### 追加
| 操作 | 内容 |
|---|---|
| **Enter**（再生中） | 現在の audio engine 位置に Marker を追加し、それを選択 |

- 追加位置は **AudioContext の再生位置**（canonical）から取得します。wall-clock や performance.now() は使いません。
- Marker ごとに **rawTick**（実際の入力位置）と **quantizedTick**（グリッド境界位置）を両方保持します。
- Quantize を切り替えても **rawTick は変わりません**。

### 選択・削除
| 操作 | 内容 |
|---|---|
| **Backspace / Delete** | 選択中の Marker を削除 |

- 新しく追加した Marker が自動的に選択されます。選択中の Marker は白線で強調されます。

### 微調整（nudge）
| 操作 | 内容 |
|---|---|
| **←（左矢印）** | 選択 Marker を 24 tick だけ時刻が早くなる方向へ移動 |
| **→（右矢印）** | 選択 Marker を 24 tick だけ時刻が遅くなる方向へ移動 |

移動は raw の位置をずらし、quantizedTick も再計算されます。Undo で元に戻せます。

## 5. Quantize（グリッド化）

トップバーの **Quantize** 欄で設定します。

| 操作 | 内容 |
|---|---|
| **Quantize** チェックボックス | ON / OFF |
| ドロップダウン | 分解能の選択 |

利用可能な分解能：

| 選択 | 意味 |
|---|---|
| `1 bar / 8` | 1小節を 8 分割（デフォルト。4/4 なら 8 分音符相当） |
| `1/4` | 4分音符ごと |
| `1/8` | 8分音符ごと |
| `1/16` | 16分音符ごと |
| `1/32` | 32分音符ごと |

**考え方**
- ON のとき、Marker は最も近いグリッド境界の **quantizedTick** になります。実際に入力した **rawTick は保たれ**ます（例：Grid からずれた位置で押しても、実際の位置とグリッド上位置の両方が保持されます）。
- OFF のとき、quantizedTick は rawTick と一致します。
- 表示される effectiveTick は、ON なら quantizedTick、OFF なら rawTick です。

---

## 6. Chord Region（コードの区間）

隣接する Marker の間に **Chord Region** が生成されます。

```text
Marker A ── Marker B ── Marker C
    Region 1 ─┘   └── Region 2
```

- 半透明の緑帯として表示されます。
- 隣接は位置順（effectiveTick）で判定します。挿入順がバラバラでも正確な区間になります。
- Region は将来の Chord Analyzer に渡すデータ構造（startTick / endTick / startMarkerId / endMarkerId）として保持されます。**解析はまだ行いません**。
- Marker が 1 個なら Region 0、2 個なら 1、3 個なら 2、… です。

---

## 7. Undo / Redo

| 操作 | 内容 |
|---|---|
| **Ctrl+Z** | Undo（操作を戻す）|
| **Ctrl+Shift+Z** | Redo（やり直す）|

対象は「Marker の追加 / 削除 / 移動 / Quantize 設定の変更」です。トップバーの **↶ Undo / ↷ Redo** ボタンからも操作でき、実行可能時のみ有効になります。

## 8. デバッグ情報（開発時）

デバッグバーにリアルタイム表示されます。

| 行 | 内容 |
|---|---|
| `raw 322` | 現在位置の raw tick（整数） |
| `quant 320` | 現在位置を現在の Quantize 分解で量子化した tick |
| `audio 4.8s` | audio engine の現在秒（canonical 位置） |
| `bar 3 beat 2` | 現在の小節（bar）と拍（beat） |

トップバー右側のパフォーマンス表示：

| 行 | 内容 |
|---|---|
| `FPS` | 平均フレームレート |
| `ms` | 平均フレーム時間 |
| `cpu —` | CPU 側の note 更新時間（ms） |
| `gpu —` | GPU 描画時間（ms） |
| `vis —` | 表示中ノート数 |
| `rAF 60Hz · …` | フレームクロック診断（ブラウザ環境の推測） |

## 9. よく使う一連の流れ

1. `npm run dev` で起動し、**http://localhost:5173/** を開く。
2. デフォルト MIDI が自動表示される。必要なら **♪ MIDI** を押して別の曲に差し替える。
3. **♫ 音声** のファイルを選び、**▶ Play** を有効にする。
4. （任意）トラックバーで解析対象以外のトラックを非表示にする。
5. **▶ Play** で再生開始。
6. コードが変わるタイミングで **Enter** を押して Marker を打つ。
7. （任意）← / → で位置を微調整する。間違えたら **Ctrl+Z** で戻す。
8. 必要に応じて **Quantize** の ON/OFF や分解能を切り替える。
9. 隣接する Marker の間が **Chord Region** になる。

## 10. トラブルシューティング

| 現象 | 対処 |
|---|---|
| ブラウザに「No WebGL2」 | WebGL2 対応ブラウザ（最近の Chrome / Edge / Firefox）を使う |
| ノートが表示されない | デフォルトMIDIは自動表示される。表示されない場合は、**♪ MIDI** で `.mid` ファイルを選び直す。ステータスに「MIDIエラー」が出ていないか確認 |
| Play ボタンが無効のまま | **♫ 音声** で音声ファイルを選択していない。ステータスに「音声エラー」が出ていないか確認 |
| ノートの縦位置がずれる | 縦方向はMIDIの最高音〜最低音に固定される。範囲外には移動できない仕様 |
| 音が出ない | ページをクリックしてから Play（自動再生制限）。OS ボリュームの確認。対応音声形式（WAV/MP3/OGG/FLAC/M4A）を使う |
| キー操作が効かない | フォーカスが入力欄 / ドロップダウンに当たっていないか確認。ステージをクリックしてから操作 |
